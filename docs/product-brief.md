# Product brief: Barbershop

## Исходные требования

- Пользователь открывает сайт в десктопном или мобильном браузере.
- Пользователь выбирает дату, время и вид стрижки.
- На первом этапе предусмотрены мужская и женская стрижки.
- Расписанием управляет администратор.
- Пользователь может записаться и посмотреть свою запись.
- Администратор может редактировать запись.
- Клиент выбирает услугу и время, но не выбирает конкретного мастера.
- Администратор может назначить или сменить мастера после создания записи.
- Для записи клиент указывает имя и телефон; регистрация аккаунта не требуется.
- Клиент может самостоятельно отменить запись.
- Клиент может перенести запись на другое доступное время.
- Успешно созданная запись подтверждается сразу и не требует одобрения администратора.
- После создания клиент получает защищённую ссылку со случайным токеном.
- По защищённой ссылке клиент может посмотреть, отменить или перенести запись.

## Цель первой версии

Создать адаптивное веб-приложение с базовым сценарием онлайн-записи на мужскую или женскую стрижку и административным управлением расписанием и записями.

## Принятые продуктовые решения

- Клиент бронирует время, а не конкретного мастера.
- Смена назначенного мастера не должна менять клиентское бронирование.
- Для создания записи достаточно имени и телефона.
- Учётные записи клиентов в первой версии не нужны.
- Клиент может отменить или перенести собственную запись.
- Запись подтверждается автоматически после успешного резервирования свободного слота.
- Доступ клиента к записи осуществляется без аккаунта по защищённой ссылке со случайным непредсказуемым токеном.

## Пока не определено

- Есть ли ограничение по времени, после которого самостоятельная отмена или перенос запрещены.
- Каковы длительность и стоимость каждой услуги.
- В каком часовом поясе работает салон.
- Может ли администратор только редактировать записи или также создавать и удалять их.

## Предлагаемые технические решения

- Перенос создаёт новую запись, а прежнюю переводит в аннулированное состояние.
- Создание новой и аннулирование прежней записи выполняются одной атомарной операцией.
- Новый слот повторно проверяется внутри транзакции и не может быть занят другим клиентом.
- Если новый слот недоступен, перенос отклоняется, новая запись не создаётся, а исходная остаётся действующей.
- Новая запись получает собственный публичный идентификатор; связь с прежней записью сохраняется для истории.
- Отмена меняет статус записи, а не удаляет её из базы данных.
- Состояние ожидания подтверждения для записи не требуется.
- Последовательный ID, имя и телефон не предоставляют доступ к записи.
- Публичный токен должен быть случайным, непредсказуемым и уникальным.

## Не включать без отдельного решения

- онлайн-оплату;
- сеть филиалов;
- программу лояльности;
- мобильное приложение;
- AI-рекомендации причёсок;
- интеграции с SMS и мессенджерами.
