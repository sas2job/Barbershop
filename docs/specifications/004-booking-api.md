# Спецификация 004: API создания бронирования

## Контракт

`POST /api/v1/bookings` принимает JSON с `service_id` и данными бронирования:

```json
{
  "service_id": 1,
  "booking": {
    "starts_at": "2026-09-05T09:00:00+03:00",
    "client_name": "Клиент",
    "phone_number": "8-000-000-00-00"
  }
}
```

При успешном резервировании возвращается `201` и JSON с публичным токеном,
статусом `confirmed`, услугой и временем записи. Последовательный ID записи
в ответ не включается.

## Ошибки

- `404` — услуга не существует или неактивна;
- `422` — некорректные данные или занятый слот.

Операция использует `Appointments::Book`, поэтому конкурентная защита слота,
немедленное подтверждение и ограничения модели остаются едиными для HTML и
JSON сценариев.

## Просмотр и отмена

- `GET /api/v1/bookings/:public_token` возвращает статус, услугу и время записи;
- `DELETE /api/v1/bookings/:public_token` переводит подтверждённую запись в
  `cancelled` и возвращает её текущее состояние;
- неизвестный токен отвечает `404`;
- телефон и имя клиента в JSON API не возвращаются.

Отмена не удаляет запись из базы данных и не использует последовательный ID.

`PATCH /api/v1/bookings/:public_token` переносит запись на новое время. При
успехе создаётся новая запись с новым публичным токеном, а старая становится
`annulled` в одной транзакции. Если слот занят, возвращается `422`, новая
запись не создаётся, а исходная остаётся `confirmed`.

Перенос отменённой или аннулированной записи запрещён и отвечает `422`.
Неизвестный публичный токен отвечает `404` для операций просмотра, отмены и
переноса.
