# Спецификация 003: API доступных слотов

## Цель

Дать интерфейсу и будущим интеграциям JSON endpoint для получения доступных
часов без дублирования расчёта расписания в клиентском коде.

## Контракт

`GET /api/v1/availability?service_id=:id&date=:date`

Успешный ответ имеет статус `200` и форму:

```json
{
  "service_id": 1,
  "date": "2026-09-05",
  "slots": ["2026-09-05T09:00:00+03:00"]
}
```

`slots` содержит только будущие свободные часы, рассчитанные через
`Availability::FindSlots`; API не реализует собственную бизнес-логику
доступности.

## Ошибки

- `404` — услуга не существует или неактивна;
- `422` — дата не является корректной датой ISO 8601.

Endpoint доступен без клиентского аккаунта. Публичный токен записи в этом
endpoint не используется: он нужен только для просмотра и изменения уже
созданной записи.
