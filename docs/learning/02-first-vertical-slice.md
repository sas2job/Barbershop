# Модуль 2: первый вертикальный срез

## Задача

Связать модель каталога услуг с первым пользовательским сценарием: клиент открывает сайт и видит доступные услуги.

## Последовательность

1. Изучены `AGENTS.md`, план проекта, product brief, спецификация каталога, учебные заметки и история Git.
2. Определена ближайшая проверяемая задача: публичный каталог активных услуг.
3. Добавлены root-маршрут, контроллер, представление и адаптивные стили.
4. Добавлены идемпотентные seed-данные для восьми услуг из спецификации.
5. Добавлен request-тест каталога.
6. Для CI добавлен минимальный system-тест каталога.
7. Восстановлена штатная установка Importmap, которой не хватало для CI-аудита.
8. Выполнены тесты, system-тест, RuboCop, Brakeman и проверка diff.
9. Разобраны acceptance criteria и минимальный контекст для агента.

## Реализованный сценарий

Корневой маршрут открывает публичный каталог активных услуг. Услуги сгруппированы по женскому и мужскому залу; для каждой показываются длительность и цена в рублях. Неактивные услуги сохраняются в базе, но не отображаются клиенту.

## Acceptance criteria

- `GET /` отвечает успешно.
- Активные услуги отображаются в каталоге и разделены по категориям.
- Неактивные услуги не попадают в каталог.
- Цена из целых копеек преобразуется в пользовательский вид: фиксированная цена или диапазон.
- Начальные услуги можно идемпотентно загрузить через `bin/rails db:seed`.

## Техническое решение

Контроллер получает только `Service.available_for_booking`, сортирует записи по названию и группирует их для представления. Валидации и ограничения модели остаются источником правил данных; каталог не дублирует эти правила.

## Проверка

- Request-тест проверяет успешный ответ, обе категории, формат цен и отсутствие неактивной услуги.
- System-тест проверяет пользовательский сценарий через headless Chrome.
- Полный Rails test suite: 9 тестов, 32 assertions, 0 failures.
- System tests: 1 тест, 4 assertions, 0 failures.
- RuboCop: 31 файл, 0 нарушений.
- Brakeman: 0 предупреждений.
- Importmap audit: уязвимых пакетов не найдено.
- Rails boot: 8.1.3.1.
- `git diff --check`: успешно.

## Acceptance criteria следующего изменения

Для будущей фильтрации каталога согласованы критерии:

- на странице есть фильтры «Женский зал» и «Мужской зал»;
- при выборе «Женский зал» отображаются только услуги категории `women`;
- при выборе «Мужской зал» отображаются только услуги категории `men`;
- неактивные услуги не отображаются;
- тест проверяет оба сценария фильтрации.

Эти критерии пока не являются реализованной функциональностью.

## Checkpoint: минимальный контекст

Для изменения каталога агенту не нужно передавать весь репозиторий. Достаточный контекст — `AGENTS.md`, product brief, спецификация каталога, модель `Service`, контроллер и представление каталога, а также существующие тесты. План проекта задаёт направление, но не заменяет спецификацию конкретной задачи.

Acceptance criteria — это проверяемые условия, по которым определяется готовность задачи. Они описывают ожидаемое поведение, а не способ реализации.

## Важный вывод

Первый вертикальный срез связывает модель, маршрут, контроллер, представление, seed-данные и проверки. Успешный запуск CI выявил не дефект бизнес-логики, а недостающую штатную настройку Importmap и отсутствие system-теста; обе проблемы были исправлены отдельными небольшими изменениями.
